## 问答作业

### 1. 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

**SV39 页表项（PTE）的组成**（64位）：

| 位范围 | 字段 | 说明 |
|--------|------|------|
| [53:10] | PPN (Physical Page Number) | 物理页号，共44位，用于组成物理地址 |
| [9:8] | RSW | 保留给软件使用，硬件忽略 |
| [7] | D (Dirty) | 脏位，表示页面自上次清零后已被写入 |
| [6] | A (Accessed) | 访问位，表示页面自上次清零后已被访问（读/写/执行） |
| [5] | G (Global) | 全局映射位，表示该映射在所有地址空间中有效 |
| [4] | U (User) | 用户态可访问位，U=1 表示用户态程序可访问 |
| [3] | X (Execute) | 可执行位，X=1 表示该页面可执行 |
| [2] | W (Write) | 可写位，W=1 表示该页面可写 |
| [1] | R (Read) | 可读位，R=1 表示该页面可读 |
| [0] | V (Valid) | 有效位，V=1 表示该页表项有效 |

**标志位作用**：
- **V (Valid)**：页表项是否有效，无效的 PTE 会被 MMU 忽略
- **R/W/X**：控制页面的读/写/执行权限，用于实现内存保护
- **U (User)**：控制用户态是否可访问，用于隔离内核与用户空间
- **G (Global)**：用于共享内核页面，切换页表时无需刷新 TLB
- **A (Accessed)**：用于页面置换算法（如 LRU）
- **D (Dirty)**：用于判断页面是否需要写回磁盘

### 2. 缺页相关问题

#### 请问哪些异常可能是缺页导致的？

以下异常可能由缺页导致：
1. **Load page fault (Exception Code = 13)**：读取访问时页面不在内存中或权限不足
2. **Store page fault (Exception Code = 15)**：写入访问时页面不在内存中或权限不足
3. **Instruction page fault (Exception Code = 12)**：取指时页面不在内存中或权限不足

#### 发生缺页时，描述相关重要寄存器的值

| 寄存器 | 值描述 |
|--------|--------|
| `scause` | 异常原因，12=指令缺页，13=读取缺页，15=写入缺页 |
| `stval` | 引发缺页的虚拟地址 |
| `sepc` | 触发异常的指令地址 |
| `sstatus.SPP` | 发生异常前的特权级 |
| `sstatus.SIE` | 发生异常前的中断使能状态 |

#### Lazy 策略的好处

1. **减少内存占用**：只在实际访问时才分配物理页面，避免分配后未使用造成的浪费
2. **提高启动速度**：程序启动时无需加载所有页面，加快启动过程
3. **减少 I/O 操作**：只加载实际需要的页面，减少磁盘 I/O
4. **节省页表空间**：对于稀疏地址空间，只建立实际使用的映射

#### 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存？

**估算**：
- 10G 内存 = 10 × 1024 × 1024 KB = 10,485,760 KB
- 页面大小 = 4KB
- 需要的页面数 = 10,485,760 / 4 = 2,621,440 页

**SV39 三级页表结构**：
- 每个页表项 8 字节，每页 4096 字节可存 512 个 PTE
- 一级页表（根页表）：1 页 = 4KB
- 二级页表：2,621,440 / 512 / 512 ≈ 10 页（但实际需要覆盖 10G 虚拟地址空间）
- 三级页表：2,621,440 / 512 ≈ 5,120 页

**总计**：约 5,120 × 4KB ≈ **20MB** 的页表内存

#### 如何实现 Lazy 策略，缺页时如何处理？

**Lazy 策略实现**：
1. `mmap` 时只记录映射信息（起始地址、长度、权限），不立即分配物理页面
2. 将页表项标记为无效（V=0），但保存映射信息

**缺页处理流程**：
1. CPU 访问无效页面，触发 page fault 异常
2. trap_handler 捕获异常，检查 `scause` 判断为缺页
3. 从 `stval` 获取引发缺页的虚拟地址
4. 查找进程的映射信息，确认该地址是否在合法映射范围内
5. 如果合法：
   - 分配一个物理页面
   - 建立页表映射，设置正确的权限位
   - 如果是文件映射，从磁盘加载内容
   - 执行 `sret` 返回用户态重新执行
6. 如果非法：发送 SIGSEGV 信号终止进程

#### Swap 策略下页面失效如何表现在页表项(PTE)上？

在 Swap 策略下，被换出的页面：
- **V = 0**：页表项标记为无效
- **PPN 字段**：存储该页面在磁盘上的位置信息（swap slot 编号）
- **D = 1**（如果被修改过）：表示需要写回磁盘
- 其他权限位保持不变，用于恢复时重新设置

当访问被换出的页面时，会触发 page fault，OS 根据 PPN 字段找到磁盘位置，将页面加载回内存。

### 3. 双页表与单页表

#### 在单页表情况下，如何更换页表？

单页表情况下，更换页表通过修改 `satp` 寄存器实现：
```assembly
csrw satp, new_page_table_root
sfence.vma  # 刷新 TLB
```

#### 单页表情况下，如何控制用户态无法访问内核页面？

通过页表项的 **U (User)** 标志位控制：
- 内核页面的 PTE 中设置 **U = 0**
- 用户页面的 PTE 中设置 **U = 1**

当用户态程序尝试访问 U=0 的页面时，MMU 会触发异常，从而阻止非法访问。

#### 单页表有何优势？

1. **减少 TLB 刷新**：切换进程时需要刷新 TLB，但内核部分可以保留（如果使用 ASID）
2. **简化内核访问用户数据**：内核可以直接访问用户空间数据，无需切换页表
3. **减少内存占用**：不需要为每个进程维护独立的内核映射
4. **系统调用更快**：进入内核态不需要切换页表，减少开销

#### 双页表实现下，何时需要更换页表？

双页表实现下，以下情况需要更换页表：
1. **用户态 → 内核态**（trap 进入）：从用户页表切换到内核页表
2. **内核态 → 用户态**（sret 返回）：从内核页表切换到用户页表
3. **进程切换**：切换到不同进程的用户页表

#### 单页表操作系统，你会选择何时更换页表？

在单页表操作系统中，我会在以下时机更换页表：
1. **进程切换时**：每个进程有独立的地址空间，切换进程时需要切换到新进程的页表
2. **exec 系统调用时**：加载新程序时，需要创建新的地址空间

不需要在系统调用/中断处理时更换页表，因为内核和用户空间在同一张页表中，只是通过 U 位隔离。
