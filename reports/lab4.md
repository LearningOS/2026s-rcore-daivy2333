## 问答作业

### 1. 在我们的 easy-fs 中，root inode 起着什么作用？如果 root inode 的内容损坏了，会发生什么？

**root inode 的作用**：

root inode 是文件系统的根目录 `/`，在 easy-fs 中它是 inode ID 为 0 的特殊 inode。它的作用包括：

1. **作为文件系统的入口点**：所有文件的查找都从 root inode 开始，通过遍历目录项来找到目标文件
2. **存储根目录的目录项**：root inode 存储了根目录下所有文件和子目录的目录项（DirEntry），每个目录项包含文件名和对应的 inode ID
3. **文件创建的起点**：新文件创建时，需要在 root inode 的目录项中添加新的条目

**如果 root inode 内容损坏会发生什么**：

1. **无法找到任何文件**：由于所有文件查找都从 root inode 开始，如果其目录项数据损坏，系统将无法定位任何文件
2. **文件系统完全失效**：`open_file` 等函数依赖 `ROOT_INODE.find()` 来查找文件，root inode 损坏会导致所有文件操作失败
3. **系统无法启动**：initproc 等初始程序无法加载，操作系统无法正常运行
4. **数据丢失风险**：虽然实际文件数据可能还在磁盘上，但由于无法通过目录项找到它们，数据实际上"丢失"了

### 2. 举出使用 pipe 的一个实际应用的例子

**实际应用例子**：使用管道连接 `ls` 和 `grep` 命令过滤文件列表

```bash
ls -la | grep ".txt"
```

这个命令的工作流程：
1. `ls -la` 进程列出当前目录的所有文件
2. `ls` 的输出通过管道传递给 `grep`
3. `grep` 进程从管道读取输入，过滤出包含 ".txt" 的行
4. 最终输出所有 `.txt` 文件的信息

管道使得两个进程可以协作完成复杂任务，无需创建临时文件。

### 3. 如何使用 cat 和 wc 完成文件的行数统计？

**方法**：使用管道连接 `cat` 和 `wc`

```bash
cat filename | wc -l
```

工作原理：
1. `cat filename` 读取文件内容并输出到 stdout
2. 管道将 `cat` 的输出传递给 `wc` 的 stdin
3. `wc -l` 统计输入的行数并输出结果

也可以直接使用 `wc -l filename`，但使用管道展示了进程间通信的原理。

### 4. 如果需要在多个进程间互相通信，则需要为每一对进程建立一个管道，非常繁琐。请设计一个更易用的多进程通信机制。

**设计方案：共享消息队列机制**

核心思想：创建一个全局可见的消息队列，多个进程可以通过消息队列 ID 进行通信，无需为每对进程单独建立管道。

**系统调用设计**：

```rust
// 创建消息队列，返回队列 ID
sys_mq_create(name: &str, max_msgs: usize, msg_size: usize) -> isize

// 打开已存在的消息队列
sys_mq_open(name: &str) -> isize

// 发送消息到队列
sys_mq_send(mq_id: usize, msg: *const u8, len: usize) -> isize

// 从队列接收消息
sys_mq_recv(mq_id: usize, msg: *mut u8, len: usize) -> isize

// 关闭消息队列
sys_mq_close(mq_id: usize) -> isize
```

**优势**：

1. **一对多通信**：一个进程发送的消息可以被多个接收者读取
2. **命名机制**：进程可以通过名称找到队列，无需传递 fd
3. **消息缓冲**：队列可以缓存多条消息，发送者和接收者不需要同步
4. **简化管理**：N 个进程通信只需要 1 个队列，而不是 N*(N-1)/2 个管道

**实现要点**：

- 使用环形缓冲区存储消息
- 支持阻塞和非阻塞模式
- 可以扩展支持消息优先级和类型过滤
